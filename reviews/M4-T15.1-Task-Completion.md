## Implemented
Two independently-diagnosed issues, both reproduced before being fixed, plus one follow-up review finding addressed in a second commit:

**1. Real production defect — orphaned background Session (`src/ui/App.tsx`).** Every explicit exit path (`handleLeave`, `handlePlayAgain`) already called `session.destroy()`, but nothing did when `<App>` simply unmounted with a Session still live — exactly what RTL's `afterEach(cleanup)` does for every test that starts a Session and never explicitly clicks Leave/Home. Reproduced directly: a spy on `chooseMove` showed 2 calls at unmount, then 91 calls 500ms later, entirely unattended. Fixed with a ref-based, unmount-only cleanup effect:
```ts
const sessionRef = useRef<SessionPresentation | null>(null);
sessionRef.current = session;
useEffect(() => () => sessionRef.current?.destroy(), []);
```
Empty dependency array so it runs its cleanup only on a true component unmount, never on the ordinary `session → null` transition the existing handlers already drive (which would otherwise double-destroy). `destroy()` is documented idempotent, so this is safe under React StrictMode's double-mount too. Verified the leak is closed (calls stay flat, 2 → 2) and the pre-existing exact-call-count Leave Game test still passes.

**2. Inherent, bounded real-time cost under CPU contention — three flagged tests.** Every autoplay Turn crosses one genuinely real macrotask (`GameRunner`'s `yieldToMacrotask`, deliberately not fake-timer-mockable — the approved lifecycle guard), which is not eliminated by the leak fix above. Reproduced the exact reported failure (`Error: Test timed out in 20000ms`) by saturating a 2-core sandbox with 6 busy processes; after the leak fix, all three tests still completed deterministically in ~34–36s under that load — bounded, never hung. Raised each test's timeout from 20000ms to 45000ms, with the reasoning and measured worst case documented inline.

Also hardened the `beforeunload`-prevented assertion in `App.test.tsx` (flagged as able to assert before the startup warning is active): wrapped it in `waitFor` so it retries a fresh `Event` dispatch instead of asserting once immediately — same final strict expectation (`toBe(false)`), just tolerant of the reported startup race.

**3. Follow-up commit — review finding MINOR-1 (permanent regression test).** Added two permanent tests in `tests/unit/ui/App.test.tsx` (describe block `Session teardown on unmount`), replacing the throwaway repro used during diagnosis:
- Unmounting `<App>` with a still-live Session calls `SessionPresentation.prototype.destroy` exactly once (the leak regression).
- A Session already torn down via Leave Game is **not** destroyed a second time on unmount (guards the double-destroy regression a naive `[session]`-keyed cleanup would reintroduce).

Review finding NIT-1 (`sessionRef.current = session` written during render) was reviewed and accepted as-is — safe here because `destroy()` is idempotent (`SessionPresentation.ts:268`) and React StrictMode's extra mount/unmount pass targets `session === null` before any real Session exists; no code change required.
